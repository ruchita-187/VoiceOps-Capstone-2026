# ZentroMart VoiceOps

## Overview

ZentroMart VoiceOps is a voice-enabled customer support agent developed
for the ZentroMart capstone project. It was built in stages: a basic
chatbot, retrieval-augmented question answering, a multi-turn support
agent, and a voice-enabled agent using Gnani Speech-to-Text (STT) and
Text-to-Speech (TTS).

The agent transcribes customer audio, processes the request through the
support agent, and generates a text and audio reply. It also saves the
retrieved knowledge-document chunks used for the response.

ZentroMart is fictional and the supplied customer and order data is
synthetic.

## Features

-   Answers customer questions using ZentroMart knowledge documents.
-   Retrieves relevant document chunks using Sentence Transformers and
    FAISS.
-   Generates responses using the Google Gemini API.
-   Supports multi-turn conversations.
-   Performs simulated identity verification before sharing order
    details.
-   Uses mock tools for order lookup and support-ticket creation.
-   Escalates cases that require human assistance.
-   Transcribes customer audio using Gnani STT.
-   Generates spoken responses using Gnani TTS.
-   Processes one audio file or a folder of audio files.

## Requirements

-   Python 3
-   Google Gemini API key
-   Gnani API key
-   Internet access for the API services

## Installation

Clone the public repository:

``` bash
git clone <PUBLIC_GITHUB_REPOSITORY_URL>
cd <PROJECT_DIRECTORY>
```

Create and activate a virtual environment (Windows PowerShell):

``` powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Install dependencies:

``` bash
pip install -r requirements.txt
```

Create a `.env` file in the project root with your API keys:

``` env
GEMINI_API_KEY=your_gemini_api_key
GNANI_API_KEY=your_gnani_api_key
```

The `.env` file is local and must not be committed. `.env.example`
contains the required variable names without secret values.

## Build the Knowledge Base

Run this command before using retrieval-based question answering:

``` bash
python src/build_kb.py
```

This processes the Markdown knowledge documents and builds the retrieval
index used by the agent.

## Run the Agent

### Batch processing (submission command)

Run the agent on every supported audio file in an input folder:

``` bash
python run.py path/to/customer_audio_folder
```

For example:

``` bash
python run.py customer_audio
```

The batch runner accepts a folder path and invokes `src/step4_voice.py`.
For each processed audio input, the agent saves:

  -----------------------------------------------------------------------
  Output                              Description
  ----------------------------------- -----------------------------------
  `reply.txt`                         Text response generated by the
                                      agent

  `reply.wav`                         Spoken response generated using
                                      Gnani TTS

  `retrieved_chunks.json`             Retrieved knowledge-document chunks
                                      used for the response
  -----------------------------------------------------------------------

### Single audio file

A single audio file can also be processed directly:

``` bash
python src/step4_voice.py path/to/audio.wav
```

## Development Stages

**Step 1 --- Basic chatbot:** Implemented a basic customer support
chatbot using the Gemini API.

**Step 2 --- Retrieval-augmented question answering:** Added document
processing, text embeddings, FAISS similarity search, and retrieval of
relevant knowledge-document chunks.

**Step 3 --- Multi-turn support agent:** Added conversation handling,
identity verification, mock order lookup, ticket creation, and
escalation.

**Step 4 --- Voice integration:** Integrated Gnani STT and TTS to accept
customer voice messages and generate spoken responses. Added
folder-based batch processing.

## Dataset

The project uses the supplied ZentroMart capstone dataset:

-   `kb/` --- company policies, agent guides, help articles, FAQs, and
    other knowledge documents.
-   `data/` --- synthetic customer, product, order, delivery, and
    related CSV records.
-   `practice/` --- questions and multi-turn conversations for testing.
-   `tools/` --- offline mock tools for order lookup and ticket
    creation.

The dataset's fixed reference date is **20 October 2026**. Use this date
for deadline and delay calculations.

Refer to `DATA_DICTIONARY.md` for dataset field descriptions.

## Security and Data Handling

-   API keys are stored locally in `.env`.
-   `.env` and `.venv/` must not be included in the repository or
    submission ZIP.
-   `.env.example` contains variable names only.
-   The supplied customer and order records are synthetic.
-   Order verification and ticket creation use offline mock tools; they
    do not authenticate real customers.
